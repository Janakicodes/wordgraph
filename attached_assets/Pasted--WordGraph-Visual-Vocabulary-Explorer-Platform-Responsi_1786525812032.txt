# WordGraph

## Visual Vocabulary Explorer

**Platform:** Responsive Web Application
**Version:** MVP v1.1
**Status:** Product Definition

---

# 1. Product Vision

WordGraph is a visual vocabulary exploration tool that helps users discover how English words connect.

Instead of:

> Word → Definition → Memorize

WordGraph enables:

> **Word → Relationships → Explore → Understand → Remember**

The product should feel like exploring a **visual map of language**.

It combines:

* Dictionary
* Mind map
* Knowledge graph
* Personal vocabulary library

The core experience should feel closer to **Obsidian's exploration model** than a traditional vocabulary-learning app.

However, WordGraph should **not attempt to recreate Obsidian**. Obsidian is an inspiration for the personal library and graph mental model, not a feature checklist.

---

# 2. Product Positioning

### Primary positioning

> **Explore words. See how they connect. Build your vocabulary map.**

### Short description

> A visual vocabulary explorer that helps you discover and understand connected words.

### Core differentiator

Traditional vocabulary tools focus on:

* Definitions
* Flashcards
* Quizzes
* Memorization

WordGraph focuses on:

* Relationships
* Exploration
* Context
* Discovery

---

# 3. Product Principles

## 1. Graph First

The graph is the hero of the product.

## 2. Explore, Don't Test

No quizzes or forced learning mechanics.

## 3. Simple by Default

Only show information when the user needs it.

## 4. Capture First, Organize Later

Saving a word should require one click.

## 5. Semantic vs Personal

Separate vocabulary relationships from the user's personal organization.

## 6. Local First

No login required.

## 7. Curiosity Over Gamification

The product should encourage users to naturally explore one word after another.

---

# 4. Target Users

## Primary

### English learners

People who want to expand vocabulary through contextual exploration.

### Students

Students preparing for exams, interviews, writing, and academic work.

### Professionals

People looking to improve business communication and written vocabulary.

### Writers and readers

People who frequently encounter unfamiliar or interesting words.

---

# 5. User Problem

When users encounter an unfamiliar word, they typically need to perform several separate actions:

1. Look up the meaning.
2. Find pronunciation.
3. Search synonyms.
4. Search antonyms.
5. Understand usage.
6. Search related words.
7. Decide whether to save it.
8. Remember where they encountered it.

Existing dictionary experiences provide the information but don't encourage **exploration between words**.

WordGraph turns vocabulary lookup into a connected experience.

# 10. Graph Design

The graph should feel like a **knowledge map**, not a conventional mind map.

Do NOT use:

* colorful circles
* bubble nodes
* heavy borders
* large cards
* excessive arrows

Use:

* typography
* whitespace
* subtle lines
* scale
* restrained color
* smooth motion

The center word is the visual anchor.

---

# 11. Relationship Types

Only three semantic relationship types exist.

## Synonym

Words with similar meanings.

Color:

Muted Green

Example:

Pragmatic → Practical

---

## Antonym

Words with opposite meanings.

Color:

Muted Red

Example:

Pragmatic → Idealistic

---

## Related

Contextually connected vocabulary.

Color:

Muted Blue

Example:

Pragmatic → Strategy

---

# 12. Relationship Rules

The graph must not become a dumping ground of vaguely associated words.

### Synonyms

Must have substantially similar meaning.

### Antonyms

Must represent a meaningful conceptual opposite.

### Related

Should primarily represent:

* contextual associations
* commonly connected vocabulary
* concepts closely associated with the word
* word-family relationships where useful

Avoid weak or arbitrary associations.

---

# 13. Graph Density

Do not display every possible relationship immediately.

Default:

Show the strongest approximately **5–8 connections**.

If more exist:

> * 12 more

Allow the user to expand.

This keeps the graph readable.

---

# 14. Graph Navigation

Users can:

* Click a word
* Pan
* Zoom
* Reset
* Drag the graph
* Center the selected word

### Clicking a word

The selected word becomes the new center.

Use a smooth 300–500ms transition.

Do NOT reload the page.

Do NOT flash or rebuild the entire interface abruptly.

The experience should feel like moving through a map.

---

# 15. Exploration Path

Track the user's current exploration path during a session.

Example:

```text
Pragmatic
   →
Practical
   →
Feasible
   →
Realistic
```

Display this subtly as:

> **Your exploration**

This is not gamification.

It simply helps users understand where they've travelled.

Allow the user to click a previous word to return to it.

# 21. Personal vs Semantic Graph

This distinction is important.

## Semantic Graph

Generated by WordGraph.

Relationships:

🟢 Synonym
🔴 Antonym
🔵 Related

## Personal Graph

Created through the user's actions.

Includes:

* Saved words
* Collections
* Tags
* Notes

Do not mix these concepts visually by default.

---

It should be **Obsidian-inspired**, but intentionally simpler.

The MVP Library has:

User-created groups.

### Notes

Personal context.

### Tags

Lightweight organization.

# 41. North Star Metric

A meaningful exploration is:

1. User opens/searches a word.
2. User interacts with at least one relationship.
3. User continues exploring.

Initial load:

< 2 seconds on a reasonable connection.

< 300ms target.

# 51. Accessibility

Do not rely solely on color.

Every relationship must have a semantic label.

Examples:

> Practical — synonym of Pragmatic

> Idealistic — antonym of Pragmatic

> Strategy — related to Pragmatic

Support:

* keyboard navigation
* screen readers
* visible focus
* adequate contrast
* reduced motion

# 52. MVP Definition of Done

The MVP is successful if a user can:

1. Open WordGraph.
2. Search for a word.
3. See the word at the center of an interactive graph.
4. Understand its meaning.
5. See synonyms, antonyms, and related words.
6. Understand why a word is connected.
7. Click a connected word.
8. See it become the new center.
9. Continue exploring.
10. See pronunciation.
11. View two example sentences.
12. Reveal a memory trick.
13. Save a word.
14. Organize saved words into collections.
15. Add tags.
16. Add personal notes.
17. View their saved vocabulary.
18. View their personal vocabulary graph.
19. Export their data.
20. Return later without creating an account.

# 53. The Product Test

Before adding any feature, ask:

> **Does this make exploring and understanding connected words better?**

If the answer is no, it probably doesn't belong in the MVP.

# 55. Long-Term Vision

The long-term opportunity is to become a **personal vocabulary knowledge graph**.

A user's library gradually becomes a map of words they have encountered, understood, and personally connected with.

The evolution is:

### V1

Explore words.

### V2

Build your vocabulary map.

### V3

Build your personal language knowledge base.

The product should never lose its core simplicity.
